⌄
CarrierConfig 读写策略非持久覆盖、读回验证与冲突保护›

模块只写入已声明的 IMS 配置键，写入后会重新读取并验证。检测到其他工具修改同一键时，会保留冲突并停止自动覆盖。

SIM 选择与恢复按当前活跃卡槽匹配，不使用固定 subId›

恢复原值只处理本模块记录且仍由本模块持有的键。系统重载 CarrierConfig 后可能需要人工重试或重启。

安全边界不修改系统分区，不关闭 SELinux›

root runner 通过 KernelSU 的 uid 0 运行，不安装辅助 APK，不依赖 Shizuku、Sui、Zygisk 或联网服务。

关于 TurboIMS Next

独立 KernelSU Next 模块，复用 TurboIMS 的 IMS CarrierConfig 映射。它不保证运营商 provisioning 或 IMS 注册，只报告实际读写和读回结果。
